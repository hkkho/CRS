## Assumptions and design choices

- `CoreStateVersion` remains the global P2-T03 commit epoch. Its initial value
  is explicit and may be nonzero, preserving the existing synthetic
  `CoreStateVersion=100` examples.
- `SpatialStateVersion` and `PowerSnapshotVersion` are distinct global
  acceptance counters that advance together exactly once for an accepted
  P2-T02 solve and its bound power snapshot. Invalidation is separate from
  counter value; an invalid binding uses `NotApplicable` rather than zero.
- `NuclideStateVersion` remains per persistent bundle identity. It increments
  once for an accepted I/Xe inventory transaction, moves with the bundle,
  remains in the discharge record, and uses an explicit fresh-fuel template
  value for inserted bundles.
- A failed or stale operation restores the complete lifecycle state with the
  rest of the transaction. No compensating increment, hidden default, or
  inferred reference value is introduced.
- Aggregate observables use canonical scope and `SnapshotDigest` for the
  ordered multi-bundle nuclide state; bundle-scoped observables use the exact
  owning bundle version. This avoids pretending a single scalar version
  represents an unordered aggregate.
- The lifecycle amendment is documentation-only. Existing numerical equations,
  units, event ranks, provisional-threshold authority, and G2-C05 plan
  amendment remain authoritative and unchanged.
