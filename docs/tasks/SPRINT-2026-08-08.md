## Sol review cadence, findings, and resolutions

The reduced cadence was followed by consolidating P2-T05 corrections and
reusing the same Aristotle reviewer for final dispositions instead of spawning
additional independent reviewers for each local fix. G2 used one fresh
empty-context `gpt-5.6-sol` gate review; no second reviewer was spawned after
the gate failed because no corrective change was authorized.

P2-T05’s initial review failed on seven themes. Consolidated correction rounds
returned fail counts of `7, 5, 5, 6, 3, 5, 6, 5`; the final disposition was
PASS with no residual severity findings. Resolved themes included closed scope
tokens and subtype discriminants, explicit per-quantity value kinds and
structured evidence, canonical byte widths/tags/UUIDs, vector/profile order,
event-body schemas, invariant ordinals, regional power, delta-k applicability,
and typed refuelling position binding.

G2’s unresolved findings were:

1. Complete T4 requires actual EditMode, PlayMode, and desktop-player smoke;
   the available script only provides import/compile smoke.
2. Power/spatial/nuclide snapshot-version initialization, increments,
   invalidation, rollback, and serialization relationships are not one closed
   cross-spec lifecycle.
3. RRS command due-time construction, zero-delay behavior, enqueue/consume
   order, and command-generation event rank are not deterministic enough.
4. Refuelling rollback does not cover the later-added I/Xe inventory/version/
   digest state.
5. Plan requirement 13 calls for quantity-specific provisional tolerances,
   while P2-T05 defers all numeric thresholds; this cannot be resolved by
   inventing values.
6. The P2-T05 report describes its focused inline command rather than printing
   the complete runnable assertion command, leaving an exact-command audit gap.

These are recorded in [`docs/gates/G2.md`](../gates/G2.md); no workaround or
unapproved specification change was made.
