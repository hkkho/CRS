## Assumptions and design choices

- Unity 6.3 is the current Unity 6 LTS line. `6000.3.21f1` was the newest 6.3 LTS patch returned by Unity's release API on 2026-08-06; the exact revision is pinned to prevent patch drift.
- Unity CLI `1.0.0-beta.3` was the latest official CLI release listed on 2026-08-06. It remains explicitly experimental and optional.
- The direct editor batch-mode wrapper is the stable fallback. The CLI is not required at runtime and the Unity Pipeline package was not added.
- Core remains a `netstandard2.1` project outside Unity. A script generates the DLL for Unity, avoiding duplicated source, a Unity-to-Core source link, or Unity metadata in `src/ReactorSim.Core`.
- The plugin is explicitly referenced by only `ReactorGame.Unity`; it is not automatically exposed to unrelated Unity assemblies.
- `BootstrapAdapter` is intentionally empty. It establishes the adapter assembly without inventing simulation APIs or presentation behavior.
- The project manifest contains no optional Unity package. The licensed editor generated the standard project settings, which were captured without manual mobile or gameplay configuration.
- Unity CLI and editor installation were explicitly authorized by the user. No module-license auto-accept flag was passed, and no mobile module was requested.
- License activation was not inferred from installation permission. The user separately authorized the Personal activation flow, completed Unity account sign-in, and personally accepted Unity's updated terms; no account credential or license artifact was written to the repository.
- The smoke requires a unique marker written only after the Core plugin, adapter assembly, and bootstrap scene checks pass. This prevents a launcher-level zero exit from masking an editor startup failure.

### False-positive guard and build repeatability probe - T0/T1

```powershell
$validationRoot = Join-Path ([System.IO.Path]::GetTempPath()) `
    'candu-p0-t05-20260807-license-check'
$failedAsExpected = $false
try {
    & '.\tools\Test-UnityImport.ps1' `
        -ArtifactsPath (Join-Path $validationRoot 't4') `
        -LogPath (Join-Path $validationRoot 'unity-import.log')
}
catch {
    if ($_.Exception.Message -ne `
        'Unity exited without producing the import/compile smoke success marker.') {
        throw
    }
    $failedAsExpected = $true
}
if (-not $failedAsExpected) {
    throw 'The smoke unexpectedly reported success without an active Unity license.'
}
if (Get-ChildItem -LiteralPath (Join-Path $validationRoot 't4') `
    -Filter 'unity-smoke-*.success' -File -ErrorAction SilentlyContinue) {
    throw 'A success marker was emitted despite the license failure.'
}

$artifacts = Join-Path ([System.IO.Path]::GetTempPath()) `
    'candu-p0-t05-determinism-probe'
& '.\tools\Prepare-UnityCore.ps1' -ArtifactsPath $artifacts
$first = (Get-FileHash -Algorithm SHA256 -LiteralPath `
    'unity\ReactorGame\Assets\Plugins\ReactorSim.Core.dll').Hash
& '.\tools\Prepare-UnityCore.ps1' -ArtifactsPath $artifacts
$second = (Get-FileHash -Algorithm SHA256 -LiteralPath `
    'unity\ReactorGame\Assets\Plugins\ReactorSim.Core.dll').Hash
if ($first -ne $second) { throw 'Same-path Core plugin rebuild was not stable.' }
```

Result: exit code 0 for the negative diagnostic harness. The marker guard caught `Unity exited without producing the import/compile smoke success marker.`, and no marker file existed. The first licensed run then exposed a Windows PowerShell GUI-process timing race: Unity completed successfully and wrote the marker after the wrapper had already checked. `Start-Process -Wait` closed that race but could wait indefinitely on Unity's persistent compiler-server descendant. The final wrapper uses a direct `System.Diagnostics.Process` handle and `WaitForExit()` so it waits for only the editor PID, then reads that process's exit code and validates the marker. The final licensed run passed in 8.3 seconds. Two no-incremental Core plugin builds using the identical artifacts path both produced SHA-256 `CDA042EA8A4C8C5FC077A09DEAA378321494375BFA1DF55AF6CBC2707F27BBDE`. Builds using different artifacts paths produced different hashes, so the discrepancy is path-sensitive build metadata rather than same-input nondeterminism; no determinism trigger fired.
