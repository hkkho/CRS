# P4-T06-R2C - final Candu6 source-to-P2-T02 mapping authority audit

## Outcome

Status: BLOCKED

This bounded task completed the final source-capability and authority audit
for the same-pinned Candu6.x2m candidate. The audit confirms that the source
can provide candidate bundle/channel power records, source geometry metadata,
source volumes, per-fission-energy records, and internal TRIVAC/BIVAC solver
inputs. It does not provide an authority-backed, path-free export that binds
those records to the frozen P2-T02 node and coefficient contract.

The technical block is therefore isolated to an owner-approved source-to-Core
mapping decision or specification addendum. In particular, this task cannot
admit the candidate by treating DONJON diffusion/leakage fields or BIVCOL unit
matrices as P2-T02 conductances, by selecting one side of the source volume
unit inconsistency, or by treating source array order as `ChannelId` and
`BundlePosition` identity.

Effectiveness: BLOCKED

R2B already established the successful source run and the exact production
counts: 380 channels, 12 bundles per channel, 4,560 bundle slots, 380
`POWER-CHAN` values, and 4,560 `POWER-BUND` values. This task does not rerun
that case or promote its source assertion to a project golden value.

The additional pinned-source audit found:

1. `SectDtrivac.tex` describes an internal TRIVAC system matrix and tracking
   records, including permutation/index data. It does not define a
   `T_g`/`B_g` export with P2-T02 endpoint keys and `m^2` units.
2. `SectDbivac.tex` defines `/BIVCOL/` records as unit mass, stiffness, nodal
   coupling, and related matrices. These are discretization ingredients, not
   P2-T02 preassembled edge or boundary conductances.
3. `SectDfluxunk.tex` documents leakage coefficients such as `DIFFHET` and
   buckling-related records. `DLEAK.f` creates a delta macrolib by changing
   `DIFF` or `NTOT1`; neither is a P2-T02 conductance binding.
4. `FLPDRV.f` writes `POWER-CHAN`, `POWER-BUND`, `VOLU-BUND`, `FLUX-BUND`, and
   `FLUX` records. `FLPFLB.f` aggregates mesh volumes and fluxes by source
   fuel-map indices, and `FLPOWB.f` computes bundle power from flux, H-factors,
   mesh volume, and an eV-to-J conversion. These routines prove candidate
   source outputs, not a P2 node identity or a frozen coefficient mapping.
5. `SectPOWER.tex` documents `POWER-BUND` and `POWER-CHAN` as `kW`, while its
   `VOLU-BUND` entry is labeled `cm^2`; the same source family reports total
   volume in `cm^3`, and the CPO volume documentation uses `cm^3`. This is a
   source-record unit conflict that must be resolved by an approved decision,
   not by an implementation assumption.
6. `SectDFMAP.tex` identifies source `POWER-BUND` as a channel/bundle array and
   `FLPFLB.f` iterates bundle position before channel. That is useful source
   provenance, but P2-T01 explicitly forbids deriving node identity or flow
   direction from array order. The Candu6 fuel-map labels do not constitute the
   project’s explicit reciprocal adjacency, boundary-face, or flow-direction
   records.

## Admission matrix

| P2-T02 field or contract | Source candidate and evidence | Admission disposition |
|---|---|---|
| `V_i` in `m^3` | `VOLU-BUND` and source volume accounting; source documents include both a `cm^2` label for `VOLU-BUND` and `cm^3` volume records. | **Not admitted.** The unit conflict and missing explicit `(ChannelId, BundlePosition)` binding require an approved source-unit decision and a path-free node manifest. |
| `E_f,i` in `J` | CPO `ISOTOPES-EFJ` is documented in joules per isotope; `FLPOWB.f` uses an eV-to-J conversion while applying H-factors. | **Not admitted.** A source convention and explicit node-level fission-energy binding to the P2 game-power convention are missing. |
| preassembled `T_g,ij` in `m^2` | TRIVAC/BIVAC internal system construction, `BIVCOL` unit matrices, `DIFF`, and `STRD`/leakage-related records. | **Not admitted.** P2-T02 forbids deriving conductance from `D_g`/`STRD`; no source field exports the required canonical reciprocal edge key and shared conductance. |
| preassembled `B_g,if` in `m^2` | Source boundary codes and leakage/buckling data identify numerical boundary context only. | **Not admitted.** No approved boundary-face conductance export or P2 face-key binding exists. |
| explicit node identity | Candu6 fuel-map labels and source `NCH`/`NB` counts; source power arrays use channel/bundle dimensions. | **Not admitted.** A project mapping from source keys to zero-based `ChannelId` and `BundlePosition` is absent; array order cannot supply it. |
| flow direction and topology | Source geometry/fuel-map metadata and boundary codes. | **Not admitted.** P2-T01 requires explicit flow direction, reciprocal neighbors, every cardinal face outcome, and `EndA`/`EndB` records; these are not supplied as a project topology manifest. |
| node observables | `POWER-BUND` and `POWER-CHAN` candidate records; source docs identify power records as `kW`. | **Candidate only.** No P2-T05 `ObservableRecord` binds scope, state/time, node key, source normalization, and comparison profile. |
| normalization | Source power totals and source-specific MW/kW/W conversions. | **Candidate only.** No approved binding to the P2 caller-supplied SI `P_target` and no project tolerance; the R2B ~40 W source-internal difference is not an acceptance threshold. |

This matrix is an audit artifact, not a new public schema and not a technical
approval. It deliberately contains no derived conductance values, selected
geometry formula, guessed volume conversion, or inferred array identity.

## Required decision to unblock admission

One of the following must be recorded by an approved task/specification
authority before R2C can close:

1. a path-free, source-produced export containing the exact P2-T02 fields and
   keys, including explicit units, topology, direction, normalization, and
   node observables; or
2. an approved P2-T02 addendum/ADR authorizing a reduced-model coefficient
   generation convention and explicit source mapping, including the
   `T_g`/`B_g` construction, volume unit, per-fission-energy convention,
   topology identity, normalization, and provenance rules; or
3. an explicit decision to abandon DONJON5 as a direct coefficient/reference
   source and continue only with a separately approved synthetic/reduced
   model boundary, with the affected P4 comparison scope removed or
   re-authorized at the appropriate gate.

The user’s redistribution-rights and reduced-runtime confirmation satisfies
the artifact/legal boundary only. It does not choose among these technical
decisions, and G2’s forced closure does not supply one.

The P2 authority audit also confirmed:

- P2-T01 requires explicit zero-based node IDs, reciprocal adjacency,
  boundary-face records, and flow direction independent of array order.
- P2-T02 requires finite positive SI `V_i`/`E_f,i`, exactly one shared
  preassembled `T_g` per reciprocal edge, and one keyed `B_g` per required
  boundary face; `D_g` is not runtime input and no unapproved geometry formula
  may derive conductances.
- P2-T05 requires exact observable scope, keys, state/time, units,
  normalization, profile, and evidence before reference/golden admission.
