# P5-T11 - complete-state burnup commit and stale-binding correction

## Outcome

Status: INCOMPLETE pending the same-context high-effort G5 disposition.

P5-T11 implements the bounded corrective scope identified by the G5 review.
The new complete-state burnup boundary requires an accepted complete power
snapshot and valid lifecycle binding, computes every left-endpoint energy and
burnup update in canonical bundle order, performs and stores every next-state
coefficient lookup, advances explicit time and `CoreStateVersion`, invalidates
the old current-power binding, and retains append-only power history. The
operation constructs all proposed inventory and lifecycle state before
returning, so an invalid table lookup leaves the source state untouched.

The legacy energy helper now also invalidates stale current power and
coefficient bindings. A strict complete-refuelling overload performs all
post-shift coefficient lookups before the lifecycle commit. The tests compose
complete snapshot -> burnup -> coefficient lookup/spatial recompute -> accepted
snapshot -> strict refuelling, and verify stale-binding rejection, discharge,
history retention, rollback, and repeatability.

Effectiveness: SUCCESS for the implementation and validation slice; gate
closure remains pending the required independent review.

## Assumptions and design choices

- The frozen left-endpoint rule remains `Delta_E = P * Delta_t` and
  `B = InitialBurnup + CumulativeFissionEnergy / HeavyMetalMass`; no equation,
  unit, sign, tolerance, or golden value was selected or changed.
- The complete burnup transition stores the newly looked-up coefficient
  identity while marking current power and power-snapshot identity
  `NotApplicable`; the next spatial solve is therefore still mandatory.
- Append-only `PowerHistory` is retained through burnup and strict refuelling;
  fresh inserted bundles begin with an empty history and a new post-shift
  coefficient binding.
- The public no-table complete-refuelling overload is preserved for existing
  bounded P5-T09 compatibility tests. The new strict overload is the
  complete-state path used by P5-T11 and performs post-shift lookup before
  commit.
- Applicable P1-T08 literature rows are `S1-R07`, `S4-R03`, `S4-R04`, `S5-R05`,
  and `S6-R05`. They provide context/methodology or candidate-design evidence
  only; the frozen refuelling/burnup specification and existing approved
  reduced-model boundary remain the authorities.
- Direct CANDU/DONJON5 production authority, full-core coverage, mobile, and
  Unity evidence remain outside this task and are not implied by the tests.
