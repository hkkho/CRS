## Assumptions and design choices

- `SimulationClockV1` stores explicit nonnegative SI seconds and a UInt64 step
  index. `TryAdvanceBy` accepts only a finite positive interval that advances
  representable time; `TryAdvanceTo` rejects backward targets. No wall-clock or
  Unity frame value is consulted.
- `SimulationCommandV1` is a scheduling envelope over the already-approved
  event owner/body/state-binding contracts. Named refuelling, burnup, and
  control bodies remain deferred; this task never executes a command.
- `CommandQueueV1` keeps the immutable allocated-command identity registry and
  pending commands. It validates the half-open sequence range, rejects duplicate
  identities/sequences independent of input order, and orders pending commands
  by `(DueTime, EventRank, Sequence, CommandId)`.
- Allocated identities are canonicalized before first-failure validation so an
  empty-ID diagnostic is input-permutation invariant. Enqueue preflights the
  actual `Int32` collection-count limit before deriving the next immutable
  queue, while the serialized contract remains UInt32-counted.
- A queue stores both its exact simulation time and step boundary. Enqueue
  requires an exact pair; due release may move only to a later paired clock
  boundary and rejects missed due times or mismatched time/step advancement.
- Signed negative zero is rejected for all clock and command time fields using
  the IEEE sign bit. No tolerance, equation, normalization, or golden value was
  introduced.
