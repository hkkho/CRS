# P2-T01 - Topology, indexing, units, and boundary specification

## Outcome

Status: COMPLETE

Created the candidate engine-neutral topology contract for the 380-channel,
12-position production model. The specification makes identifiers, slot-level
connectivity, reciprocal edges, flow orientation, boundary-face coverage, and
units explicit; separates runtime topology loading from offline P1 reference
validation; and refuses to infer geometry or time mappings from the two smoke
cases. A first Sol review found four substantive issues and a final review
passed after the candidate was corrected.

No Core, CLI, Unity, schema, parser, reference artifact, equation, tolerance,

## Assumptions and design choices

- P2-T01 is a Sol-led specification task in the implementation plan and is not
  a viable Luna implementation task because it makes the first topology and
  indexing decisions. A Luna worker was not substituted for the Sol review.
- `ChannelId` and `BundlePosition` are zero-based, production counts are 380
  and 12, and the contractual production slot count is 4,560. These are model
  identity decisions authorized by P2-T01, not inferred values from a private
  station map.
- `EndA` and `EndB` are abstract canonical endpoints bound to positions 0 and
  `N-1`; flow direction is explicit and never inferred from array order.
- Transverse and within-channel relations use explicit source/target slots,
  reciprocal edges, composite uniqueness keys, and exact cardinal/end-face
  coverage. The runtime loader does not consume P1 compact exports.
- The DONJON `6x6x1` and DRAGON three-record descriptions are case-level
  provenance only. No channel, bundle, burnup/time, coordinate, normalization,
  or solver meaning is backfilled from them.

### Independent Sol review and review fixes

Fresh read-only `gpt-5.6-sol` max review initially returned `FAIL` with four
findings:

1. High: EndA/EndB and inlet/outlet ordering were underdetermined.
2. High: slot connectivity, axial relations, boundary-face fields, and face
   coverage were not fully expressible.
3. Medium: runtime topology loading was accidentally coupled to P1 export
   lexemes/publication fields.
4. Medium: DRAGON/DONJON mappings overclaimed depletion/time or usable geometry.

The same reviewer also found a residual Medium ambiguity in the next pass:
neighbor/boundary composite uniqueness and the required face set were not
explicit. The specification was corrected after each review. The same reviewer
then returned final `PASS` with no residual severity findings and confirmed the
candidate safe to freeze. No review fix changed any file outside the allowed
specification.
