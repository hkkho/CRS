# P5-T01 - Declarative S4/S8 scheme metadata and position plans

## Outcome

Status: COMPLETE

declarative 4-bundle and 8-bundle refuelling scheme definitions. It validates
scheme identity, schema version, fresh-fuel-template identity, exact 4/8-count
support, ascending inserted-slot order, catalog coverage of both counts, and

directions. It does not mutate bundle inventory, resolve fuel data, integrate

## Assumptions and design choices

- The implementation follows the approved P2-T03 scheme contract: shift counts
  are exactly 4 or 8, inserted positions are canonical ascending physical
  positions, and the flow binding is `EndAtoEndB -> TowardEndB` and
  `EndBtoEndA -> TowardEndA`.
- The catalog requires both 4-bundle and 8-bundle coverage, while allowing
  multiple definitions for either count. Scheme IDs and template IDs remain
  opaque strings; no fuel-template contents are invented or resolved here.
- Position plans validate against the caller-supplied channel position count
  and the existing P2/P3 Core `int`-backed storage bound. They report positions
  only; no bundle identity, slot, event, burnup, coefficient, or lifecycle state
  is mutated.
- The P1-T08 literature digest applicability is `NotApplicable` for authority
  or numeric selection: P5-T01 uses only the approved P2-T01/P2-T03 contracts
  and selects no literature equation, constant, unit, normalization,
  coefficient, reference case, golden value, or history. Refuelling-related
  candidate rows `S1-R07`, `S4-R03`, `S4-R04`, `S5-R05`, and `S6-R05` were
  inspected as background/candidate-design evidence only and were not used as
  runtime authority.
- `G2` remains exactly `FORCED CLOSED / WAIVED`. P4-T06/G4 reference admission
  remains separate; this task uses no DONJON5 input or golden evidence and is
  eligible under the gate-overlap rule.
