The refuelled, RRS, and poison cases remain outside this task exactly as
specified by G4C.

## Assumptions and design choices

- The checker is a separate scalar/checking path. Its project contains no
  `ProjectReference`, package, native dependency, runtime data loader, or
  reference-tool dependency.
- R4 source rows are the material input authority; the reduced pack is parsed
  and compared bitwise against the source rows and its manifest/checksums are
  bound. P4-T08 coefficient fields are validated as fixture structure but are
  not used as material coefficients.
- The exact-knot and midpoint lookup follows the frozen P5-T05/R3 rule and
  derives `chi_group2` as `1 - chi_group1`; it does not independently
  interpolate or store the derived component.
- The solver uses a validated explicit three-node fixture with reciprocal edge
  records, direction semantics, complete reflective boundary-face records, and
  per-group conductances; it never derives adjacency from array position.
  The fixture binds 1.0 m3 node volume, 0.6 m2 group conductances, target power
  0.9 W, initial eigenvalue 1.0, deterministic Jacobi-v1, and the
  caller-supplied two-outer-iteration policy from P4-T08.
- Output is a new offline candidate evidence format, not a runtime schema. It
  is path-free, hash-bound, `candidate`/`Candidate`, emits typed P2-T05 scopes,
  canonical state/order identities, and leaves every profile `Deferred`.
- Invalid, non-finite, out-of-domain, incoherent, failed-inner-solve, or
  nonconverged input/state causes a nonzero CLI result and no usable last
  iterate or generated artifact.
- The owner-confirmed redistribution rights and reduced-runtime intent are
  preserved as boundary context; no raw external reference payload is copied
  into the repository.
