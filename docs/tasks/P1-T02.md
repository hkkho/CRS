# P1-T02 - Run one minimal DRAGON5 lattice/depletion smoke case

## Outcome

Status: COMPLETE

P1-T02 adds a narrowly scoped, fail-closed runner and case descriptor for one
authoritative upstream DRAGON5 `lumpSS` lattice/depletion smoke case.  The
runner stages the immutable upstream input and its two procedures only into an
external artifact directory, acquires and verifies exactly one official
source-era XMAS/SHEM Draglib outside Git, and runs DRAGON directly in the
pinned offline Linux container.  It does not add a parser, compact export,
golden dataset, C# code, DONJON work, or committed nuclear data/input/output.

Both isolated executions passed the three upstream K-EFFECTIVE assertions:
`1.329496E+00`, `1.314796E+00`, and `1.292124E+00`.

## Files created or changed

- `reference/dragon5/P1-T02-lumpSS.case.json` - machine-readable identity,
  source-era compatibility pin, licensing/no-redistribution boundary, and
  required smoke observables for the external case.
- `tools/PhysicsData/Run-P1-T02-DragonLumpSS.ps1` - the single-case offline
  runner.  It validates source/tree/blob identities, Git-LFS object/hash/size,
  executable hash, decompressed data hash/size, required result observables,
  fatal diagnostics, and a separately captured DRAGON stderr allowlist before
  writing an external run record.
- `docs/tasks/P1-T02.md` - this task report.

Pre-existing repository files were inspected and not changed.  The upstream
deck/procedures, 208,598,694-byte compressed Draglib, 410,270,876-byte
decompressed Draglib, raw result, staging area, and run records are external
artifacts and are not Git-visible repository content.

## Assumptions and design choices

- The authoritative case is Version5 v5.1.0
  `Dragon/data/lumpSS.x2m`, with `lumpSS_proc/mixA1_lumpSS.c2m` and
  `assertS.c2m`.  The source commit is
  `eee582f8594d3b7d01b65660ca1e8bef00eb6b2a`, tree
  `0d3e8f721c84b3c3b2d03e9898a8a0a9c29287d8`; staged blobs are
  `b070c3a91fc7afa586261f989dcbe410dec7063c`,
  `4ebf607cedc05186103b2c935b29a3dfd09aa435`, and
  `1b9c714fa7f45a1171e1ba80a682ee89b3cc0709`.
- Canonical upstream Git blobs are LF.  A Windows checkout may contain only
  checkout-inserted CRLF; the runner changes CRLF pairs back to LF, rejects
  bare CR, and verifies canonical byte count and SHA-256 before staging.
- The selected single asset is the official source-era compatibility object
  `l_endian/draglibJeff3p1p1SHEM295_v5p1.gz` at libraries commit
  `08a289f7e39ab22f1fbbf5c508e29e9d3757e1af`, tree
  `407adff2b52ca515f813b47503ed4611f7264775`.  It was retrieved from the
  immutable official raw URL recorded in the descriptor at
  `2026-08-07T07:48:13.6862125Z`; its Git-LFS OID and compressed SHA-256 are
  `d91f11d9b827c7b2573c216fc49f97c104886145b34979c358892d9d884758ee`.
  The runner also verifies decompressed SHA-256
  `e0b5730892efe31059c638fd4894b9420f46607dceb18e0def3894ea0ba25631`.
- This historical object supersedes P1-T01's provisional current-library pin
  only for this v5.1.0 smoke case.  The current P1-T01 object
  `9c33ee03a4de694af984e4b02461dd01a0cb7026c9a35c777394ae02a78c3a29`
  is explicitly rejected: its step-2 K-EFFECTIVE was `1.314567` rather than
  `1.314796`, a raw difference of `0.000229` (22.9 pcm).  No assertion or
  tolerance was loosened.
- The selected case/procedures lack individual license headers and the
  libraries repository remains `NOASSERTION / mixed notices`.  The official
  site describes XMAS/SHEM Draglibs as open source, but public availability is
  not treated as permission to redistribute: inputs, asset, raw output, and
  record remain external.
- The execution is direct because the slim image's `rdragon` launcher assumes
  a missing data directory.  It uses image
  `docker.oecd-nea.org/dragon/5.1@sha256:eb8ddff7d788f563f958ada277a2c8304d2dcf829ef59a35db62438397188d79`,
  `linux/amd64`, `--network none`, `--pull never`, read-only mounts/tmpfs, and
  `OMP_NUM_THREADS=1`.  The executable SHA-256 is
  `3121023a186cab6d0a56fd363bb979794fcd904f860f49439567bff4b1510cd0`;
  the image reported gfortran 13.3.0.  DRAGON stdout and stderr are separate:
  stderr must be empty or exactly the known IEEE underflow/denormal notice;
  the runner validates and records its path, size, SHA-256, and text.
