Status: COMPLETE

P9-T01 synthetic CLI command streams. It records machine-specific timing and

## Assumptions and design choices

- The P9-T02 profile manifest is observation authority only. It binds the exact
  repository P9-T01 path and SHA-256 and the runner verifies the executed path,
  not merely a repository-default file. Profile mode rejects an alternate
  `--manifest` path before measurement.
- The profile uses the P9-T01 closed case set in its approved order. Each case
  receives ten warmups and one hundred measured executions. Profile mode
  rejects `--warmup` and `--measure` overrides so the versioned sampling
  protocol cannot be silently changed.
- The measured operation is one complete public `CliApplication.Run` call per
  frozen command stream with `TextWriter.Null` sinks. `Stopwatch` and
  `GC.GetAllocatedBytesForCurrentThread` are measurement tools only; wall-clock
  values never enter simulation state or replay identity.
- Timing and allocation percentiles use the manifest's nearest-rank rule for
  p50 and p95. Command counts and UTF-8 input/stdout byte counts are workload
  descriptors, not profiler attribution or acceptance thresholds.
- The P8 synthetic CLI command streams do not invoke the Core spatial solver.
  Solver hotspot and solve-latency evidence is therefore `NotApplicable` /
  `NotMeasured` here. The existing P4-T08 static Core benchmark remains a
  separate solver observation boundary; a later P9-T03 task may profile it
  without changing equations or selecting a target.
- Android remains `Deferred/NotAvailable`: a current environment check found
  no `adb` command or representative Android device. Desktop evidence is not
  substituted for T5/G9 device evidence.
- Literature applicability: `NotApplicable`. This task consumes frozen
  synthetic gameplay contracts and selects no physics equation, constant, unit,
  normalization, convergence rule, tolerance, reference case, or golden value.
