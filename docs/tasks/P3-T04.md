## Assumptions and design choices

- P3-T04 is the first new bounded task ID assigned from the G3 corrective work
  because the prior report intentionally left the next Phase 3 IDs unassigned.
  P3-T05 is separately assigned and remains documented in its own report; no
  task IDs are combined in this update.
- Save/load requires the validated `SimulationConfiguration` as the external
  topology/data-pack authority. The archive carries the lifecycle provenance,
  digests, inventory, bindings, and snapshot state; it does not invent a
  topology codec or a data-pack payload.
- JSON is written and read through explicit Newtonsoft.Json token operations,
  with fixed field order, explicit `Applicable`/`NotApplicable` tags, strict
  lowercase UUID/hex values, canonical collection order, and no reflection
  object mapping or serializer attributes.
- The existing caller-supplied `Digest32` values remain authoritative. The
  codec preserves and validates them during round-trip; it does not replace
  them with an unapproved digest or numerical reference value.
- Replay records only `Enqueue` and `ReleaseDue` transitions already provided
  by `CommandQueueV1`. It verifies exact released-command identity order and
  returns immutable queue state. Serialization and restore require the
  validated configuration topology and current state-binding authority. It
  does not apply `EventBodyV1`, add named command bodies, mutate physics state,
  or implement atomic command application.
- Serialized lifecycle restore rejects counter rollback, invalid applicability,
  incoherent spatial/power statuses, mismatched inventory locations, stale
  topology/data-pack provenance, invalid digests, and unsupported schema
  versions before constructing a runtime object.

### Literature applicability

NotApplicable to numerical literature evidence. This is an engine-neutral
state/serialization task over already-approved contracts; no physics constant,
equation, normalization, tolerance, golden value, or reference result was
selected or changed.
