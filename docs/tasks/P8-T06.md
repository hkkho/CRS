## Assumptions and design choices

- The soak is bound to the exact approved P8-T05 policy artifact SHA-256
  `d0e6dec7199751ca0f5d5418892fe0210831e46153ff445ec13e4e84ddf49d39`, which
  itself binds P8-T02 scenario SHA-256
  `80981452f4808fae9e2c8341fc32e88640b446d386f9dbb7726c1550a2ff51a2` and
  P8-T03 scoring SHA-256
  `4b0f6d0aa3336b0560ca763bfdbf5012151289bbe9122cb1126c13f86086b91c`.
- The fixed plan `p8-t06-long-run-soak-v1` covers four policies times 16
  fresh cycles, or 64 isolated runs. Each cycle creates a new approved
  session and preserves P8-T05 action and advance command granularity.
- The monitor observes the existing runtime's explicit 100 ms wall control
  tick and state-segment decomposition. It checks returned advance identity,
  exact integer wall-time scheduling, control-tick/step progress, contiguous
  state-segment coverage, finite and monotone clocks, pending capacity,
  action/event/loss ordering, approved operating-envelope bounds, expected
  terminal-loss identity, score bounds/quality, and turn-summary cause/effect
  and count identity.
- A terminal `RecordLoss` is accepted only when its single loss record matches
  the observed approved-envelope violation. Other terminal and nonterminal
  states must remain inside the approved envelope. Invariant failures carry
  `policy=<id>.cycle=<index>` in the first diagnostic path and stop the soak.
- The aggregate digest canonically includes plan identity, cycle index, replay
  seed, outcome, simulation/wall time, score, loss/turn counts, invariant
  sample count, and replay digest. The test compares this digest and a full
  per-cycle fingerprint sequence across two complete plan executions.
- Literature applicability: `NotApplicable`. This task consumes frozen
  synthetic gameplay contracts and selects no physics equation, constant,
  unit, normalization, tolerance, reference case, or external authority.
