# P0-T04 - Formatting, analyzers, and targeted test scripts

## Outcome

Status: COMPLETE

P0-T04 adds repository-wide text and C# formatting rules, enables the .NET 10 SDK's built-in recommended analyzers and build-time code-style checks, and supplies distinct wrappers for formatting, one-test execution, and intentionally gated full-suite execution. The headless solution builds without warnings, the format check passes, and the focused wrapper runs exactly the named trivial test. No packages, production behavior, Unity assets, CI, or later-phase features were added.

## Files created or changed

- `.editorconfig` - repository-wide UTF-8/LF/whitespace rules and minimal C# formatting policy.
- `.gitignore` - excludes standard .NET build, artifact, and test-result output created by the task wrappers.
- `Directory.Build.props` - enables SDK analyzers, pins the analyzer rule set to `10-recommended`, enforces code style during builds, and treats analyzer warnings as errors.
- `tools/Check-Format.ps1` - verifies solution C# whitespace formatting without restoring packages.
- `tools/Test-Focused.ps1` - requires one test project under `tests/` and one exact fully qualified test name; outputs build artifacts outside the repository by default.
- `tools/Test-FullHeadlessSuite.ps1` - keeps T3 execution separate and refuses to run without `-ConfirmFullSuite`.
- `docs/tasks/P0-T04.md` - this task report.

The existing project files and tests were inspected but not changed. All unrelated P0-T01 through P0-T03 files and user files were preserved.

## Assumptions and design choices

- The SDK-bundled analyzers are sufficient for Phase 0, so no analyzer package was added. `EnableNETAnalyzers` is explicit because Core targets `netstandard2.1`, where SDK analyzers are not enabled by target-framework default.
- `AnalysisLevel` is `10-recommended`, matching the exact .NET 10 SDK pin and avoiding an unbounded analyzer-policy change.
- Formatting policy is intentionally small: encoding, line endings, final newline, trailing whitespace, four-space C# indentation, and deterministic `using` ordering.
- The format wrapper checks the solution's C# whitespace surface. Analyzer and code-style policy is enforced independently by the build.
- Minimal ignore rules keep SDK-generated `bin/` and `obj/` intermediates, explicit `artifacts/`, and VSTest `TestResults/` output out of task diffs.
- Focused test selection rejects wildcards and filter operators rather than accepting an arbitrary VSTest filter. This keeps routine task validation bounded to one named test.
- The full-suite wrapper is present as required by the Phase 0 work package but is a separate, explicitly guarded entry point. It was not run during this task.
- PowerShell 5.1 is the minimum supported script host for the current Windows development environment; the scripts use APIs also available in newer cross-platform PowerShell.

### Script safety guards - T0

```powershell
try {
    & '.\tools\Test-Focused.ps1' `
        -Project 'tests/ReactorSim.Core.Tests/ReactorSim.Core.Tests.csproj' `
        -FullyQualifiedName '*'
    throw 'The focused-test script unexpectedly accepted a wildcard.'
}
catch {
    if ($_.Exception.Message -notlike 'FullyQualifiedName must be one exact test name*') {
        throw
    }
}

try {
    & '.\tools\Test-FullHeadlessSuite.ps1' -ArtifactsPath $validationRoot
    throw 'The guarded full-suite script unexpectedly ran without -ConfirmFullSuite.'
}
catch {
    if ($_.Exception.Message -notlike 'The full suite is gated.*') { throw }
}
```

Result: exit code 0. The focused wrapper rejected a wildcard before invoking `dotnet`, and the full-suite wrapper rejected an unconfirmed invocation. No full suite ran.
