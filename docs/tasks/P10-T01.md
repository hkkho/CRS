# P10-T01 - Thin Unity presentation/input adapter

## Outcome

Status: COMPLETE

P10-T01 adds the first thin Unity presentation seam over the completed,
engine-neutral Phase 8 CLI/Core boundary. Phase8UnityRuntimeAdapter accepts
explicit commands, forwards them to an injected IPhase8RuntimePort, publishes
immutable Phase8UnityPresentationSnapshotV1 values, and exposes command-result
and snapshot events for later UI panels. It does not own simulation
transitions, load parameter packs, duplicate the CLI runtime, read Unity frame
time, or advance itself from Update.

The approved Phase 8 pacing boundary remains intact: wall time is an explicit
integer millisecond command; the runtime port remains responsible for the
approved 100 ms control tick, default 10x acceleration, and one-simulation-
second presentation cap. Duplicate command sequences are rejected before the
runtime port is called, and an accepted result must carry a non-null snapshot.

## Assumptions and design choices

- IPhase8RuntimePort is an injection seam rather than a new simulation
  implementation. A future host maps these commands to the existing Core/CLI
  runtime and returns the approved state projection.
- Phase8UnityInputCommandV1 owns only transport metadata and finite UI input
  values. Operating-envelope and playback-mode authority remains in the
  runtime port and approved Phase 8 parameter pack.
- The adapter sequence generator is monotonic across bind/unbind, advances past
  externally supplied sequence values, and rejects reuse. This prevents a
  double touch from reaching the runtime while leaving runtime validation and
  transactional state ownership in the port.
- The snapshot uses stable string identifiers for difficulty, playback mode,
  and outcome so the first adapter does not create a second Core enum or
  serialization authority.
- Bind fails closed when the port cannot provide an initial valid snapshot.
  Accepted command results also fail closed when their snapshot is null.
- No Unity Update, Time.deltaTime, Time.unscaledDeltaTime, DateTime, Stopwatch,
  or Core runtime transition call is present in the adapter.
