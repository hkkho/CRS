## Assumptions and design choices

- The benchmark manifest is synthetic observation authority only. It binds the
  exact approved P8-T02 scenario SHA-256
  `80981452f4808fae9e2c8341fc32e88640b446d386f9dbb7726c1550a2ff51a2`, P8-T03
  scoring SHA-256
  `4b0f6d0aa3336b0560ca763bfdbf5012151289bbe9122cb1126c13f86086b91c`, and
  P8-T05 policy SHA-256
  `d0e6dec7199751ca0f5d5418892fe0210831e46153ff445ec13e4e84ddf49d39`; the
  runner verifies those hashes against the actual repository files before
  measuring.
- The three command streams are deliberately fixed: `steady-survival-10x`,
  `controlled-response-10x`, and `boundary-loss-10x`. Each starts a named
  approved scenario and ends with `quit`; the CLI itself remains responsible
  for all scenario, scoring, loss, and replay validation.
- The measured operation is the existing public `CliApplication.Run` boundary
  with explicit command input and null output sinks. It includes CLI parsing
  and runtime execution but never samples wall time as simulation input. The
  benchmark's `Stopwatch` and allocation counter are measurement tools only.
- Warmup is 10 iterations and measurement is 200 iterations per case. The
  manifest contains `performance_target: null`; no observed microsecond or
  allocation value is a budget, acceptance threshold, or optimization mandate.
- The harness performs two captured runs per case before timing and requires
  exact output and exit-code equality. Timed runs also require exit code `0`.
- Android status is `Deferred/NotAvailable` after a read-only environment check
  found no `adb` command or attached device. A future device task owns T5/G9
  evidence; desktop results cannot be substituted for Android.
- Literature applicability: `NotApplicable`. This task consumes frozen
  synthetic gameplay contracts and selects no physics equation, constant, unit,
  normalization, convergence rule, tolerance, reference case, or golden value.
