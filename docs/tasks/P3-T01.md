## Scope and design choices

- `ChannelId`, `BundlePosition`, and `NodeKey` are explicit zero-based typed
  identities. `CoreTopology` uses canonical channel-major/position-major flat
  storage only after validating the explicit topology records.
- Channel flow direction, inlet/outlet binding, cardinal and within-channel
  neighbors, reciprocal relations, coordinate deltas, boundary labels, and
  complete cardinal-face coverage are validated without inferring topology
  from array order.
- Validation is fail-closed and returns one deterministic first diagnostic.
  Nested null records are rejected before sorting or dereferencing. Coordinate
  arithmetic is widened before comparison so `Int32` endpoints cannot wrap.
  Boundary label validation precedes duplicate-key reporting, with canonical
  ordering including classification.
- `StableId` preserves canonical UUID network/display byte order and accepts
  only exact lowercase UUID D-format text. Runtime code does not generate IDs.
- `DataPackDescriptor` owns explicit schema/version, dimensions, units-profile
  identity, and 32-byte digest fields. It does not contain a solver backend or
  physics constants.
- `SimulationConfiguration` retains explicit initial time and lifecycle
  counters; it does not infer hidden zero values.
- `BundleInventory` is a flat immutable identity/location/inventory slice.
  `BundleState` is intentionally not the complete fixed `BundleStateV1`
  projection from P2-T03; histories, power snapshots, coefficient brackets,
  nuclide envelopes, and lifecycle transitions remain future bounded tasks.
- The synthetic fixture is a two-channel, three-position explicit topology
  with reciprocal axial/transverse relations, labeled exterior faces, explicit
  endpoint faces, a compatible data-pack descriptor, and six stable bundle IDs.
