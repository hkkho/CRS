# P0-T08 - Engine-neutral JSON serialization strategy

## Outcome

Status: COMPLETE

P0-T08 accepts ADR-011 and pins an engine-neutral JSON mechanism without
defining a save, replay, data-pack, or other public schema. Core uses
Newtonsoft.Json through the exact NuGet range `[13.0.2]`; Unity uses the
official `com.unity.nuget.newtonsoft-json` package `3.2.2`, which Unity
documents as corresponding to upstream `13.0.2`. Future runtime codecs must
handle named JSON tokens explicitly and must not use reflection object mapping
or serializer attributes.

The dependency boundary is executable rather than documentary. The Unity
preparation script validates all pins, copies only `ReactorSim.Core.dll`, and
rejects a manually copied Newtonsoft DLL. A Core-owned manual token probe runs
under the focused test, T3, Unity editor import, and a command-line-gated built
player hook. The clean player contained file-version `13.0.2` Newtonsoft.Json
with SHA-256
`A56146202232958F46BD6A28B5A7DA166AEA123EE0D646735A46E5C341DFBF1F`,
exactly matching the resolved Unity package's `Runtime/AOT` assembly. The
player emitted the unique success marker only after the Core probe completed
and exited with code 0.

## Assumptions and design choices

- The NuGet reference uses `[13.0.2]`, not plain `13.0.2`: NuGet documents the
  bracketed form as an exact version match, while a bare version is a minimum.
- Unity package 3.2.2 is deliberately paired with older upstream Json.NET
  13.0.2 rather than independently selecting the newest NuGet release. Unity's
  official package documentation and resolved `package.json` identify that
  correspondence, and its .NET Standard 2.0 asset has no transitive package
  dependency for Core's target.
- Runtime code may use `JsonReader`/`JsonWriter` or equivalent manual
  LINQ-to-JSON token operations. `JsonConvert` object serialization,
  reflection-backed `JsonSerializer`, `FromObject`/`ToObject`, contract
  resolvers, and serializer attributes are outside this decision.
- The probe payload is an infrastructure sentinel only. It has no schema
  version, domain field, unit, compatibility promise, or persistence use.
- A narrowly public, engine-neutral probe permits a static Core-to-adapter call
  without making Core name a Unity presentation consumer through
  `InternalsVisibleTo`. Core contains no Unity lifecycle code.
- The player hook does nothing unless both unique smoke arguments are present.
  It writes the marker only after the Core token reader/writer succeeds and
  then calls `Application.Quit(0)`; it owns no simulation state or normal
  runtime behavior.
- Unity's package supplies separate editor and AOT player DLLs. Static calls
  keep the selected token path visible to UnityLinker/IL2CPP analysis, and the
  clean Windows player executed the package AOT asset. The installed Windows
  standalone module itself exposes only Mono player variations, so this is
  compatibility and dependency evidence, not an actual IL2CPP compilation.
- Official primary sources consulted were Unity's package manual, Unity's AOT
  and managed-stripping manuals, NuGet's package/version pages, and Json.NET's
  manual token-reading documentation. Links are recorded in ADR-011.
