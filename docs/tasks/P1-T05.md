# P1-T05 - DRAGON5 lumpSS parser and compact exporter

## Outcome

Status: COMPLETE

Implemented a Python-standard-library, fail-closed parser/exporter for exactly
the P1-T02 DRAGON5 `lumpSS` case. It accepts only the pinned P1-T02 descriptor
and its SHA-256, parses the three required runtime blocks in strict source
order, and writes the canonical P1-T04 compact export only to a new
external/private path. It does not retain, embed, or redistribute a DRAGON
listing, create golden/reference approval, change a schema, or add runtime
simulation code.

The committed listing is hand-authored, minimal, and explicitly marked
synthetic/parser-only/not-golden/not-reference-approval. It contains only the
already documented source KINF lexemes and count evidence. The expected compact
fixture has the required `candidate_reference` status, which remains
`external-private` and `not-approved`; it is not an approval decision.

## Assumptions and design choices

- The parser accepts only the repository's exact P1-T02 descriptor path and
  frozen descriptor SHA-256. Provenance is read from that descriptor and no
  run-specific field is emitted.
- A source block is accepted only as `FLU2DR` final external convergence, then
  `++ TRACKING` `FINAL KINF`/`FINAL KEFF`/`B2`/`PRECISION`, then a successful
  assertion with its required `|>nnnn` trailer. All scalar fields are parsed
  invariantly and checked finite; only the three documented KINF lexemes are
  exported.
- The runtime completion marker and normal-end marker must follow all three
  blocks in order. An echoed `ECHO "test lumpSS completed" ;` line is ignored
  and cannot satisfy completion.
- UTF-8 BOM, invalid UTF-8, NUL, CR/CRLF, fatal diagnostics, nonconvergence,
  NaN/infinity, malformed or ambiguous marker syntax, missing/extra markers,
  wrong order, and unexpected KINF spellings fail closed.
- Output must have a conservative `.json` basename, resolve both lexically and
  physically outside the repository, use an existing non-escaping parent, not
  collide with input/descriptor, and be created with exclusive no-overwrite
  semantics.

    [ref]$tokens,
    [ref]$parseErrors)
