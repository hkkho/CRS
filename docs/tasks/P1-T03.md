# P1-T03 - Minimal DONJON5 static-core smoke input and runner

## Outcome

Status: COMPLETE

Added one pinned, offline DONJON5 static-core smoke-case descriptor and a PowerShell runner. The runner stages the exact upstream deck, assertion procedure, and two prepared HDF5 group-constant files outside the repository; validates their source/tree/blob/hash identity; and runs the pinned DONJON executable in a local Linux/amd64 container with no network access.

The runner preserves the upstream `assertS` K-EFFECTIVE assertion and verifies its actual runtime success record, the exact FLDDIR multiplication factor, completion and normal-end records, final FLDDIR convergence evidence, and the exact two-line runtime-warning allowlist. It fails closed on source/container drift, unexpected stderr, fatal diagnostics, convergence failure, extra warnings, missing records, or differing expected observables.

Independent Sol review gave a final PASS after the repeated focused T3 runs. This task does not add a parser, compact export, production solver logic, or any committed external input/output artifact.

## Assumptions and design choices

- The authoritative source remains Version5 `v5.1.0` at commit `eee582f8594d3b7d01b65660ca1e8bef00eb6b2a` and tree `0d3e8f721c84b3c3b2d03e9898a8a0a9c29287d8`, as established by P1-T01.
- The selected upstream case is `Donjon/data/AFA_180_310_type1_dual.x2m`: a 6x6x1 reflective, two-mixture static core using the prepared `AFA_180.h5` and `AFA_310.h5` group constants.
- Text inputs are normalized only from checkout-inserted CRLF pairs to their pinned canonical LF bytes before hash validation; bare carriage returns fail. This is required because the direct DONJON run does not accept the Windows CRLF form of the deck.
- The prepared HDF5 files are ordinary pinned Git blobs, not Git-LFS nuclear-data assets. They embed CEA/AREVA copyright/export metadata (including `AL: 0D001` and `ECCN: N`), so all source inputs, staged copies, raw listings, and run records remain private and external. They must not be committed, vendored, mirrored, published, or redistributed without separate legal/export-control approval.
- The direct executable `/dragon/5.1/Donjon/bin/Linux_x86_64/Donjon` is used inside the digest-pinned image with `--platform linux/amd64`, `--network none`, `--pull never`, a read-only root filesystem, and `OMP_NUM_THREADS=1`, `TZ=UTC`, `LC_ALL=C`, and `LANG=C`.
- The raw listing is retained only externally. Its SHA-256 is provenance, not a golden acceptance criterion, because non-semantic CLE-2000 listing annotations and timing/memory diagnostics vary across otherwise equivalent runs. No upstream tolerance, assertion, equation, unit, sign convention, or convergence setting was changed.
