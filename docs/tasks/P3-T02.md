## Assumptions and design choices

- `VersionLifecycleV1` accepts a complete structural topology and canonical
  bundle locations as in-memory validation context. Same-size but structurally
  different topologies are rejected.
- Spatial acceptance requires candidate topology/data-pack versions and
  digests, state digest, bundle nuclide versions, and exact current simulation
  time before either lifecycle counter is advanced. The transition is
  immutable and rejects overflow.
- `StateSnapshotV1` is intentionally bounded to an accepted power-snapshot
  binding. Initial/unbound snapshots, stale time, relocated bundles, and
  mismatched snapshot ID/version/digest are rejected. Generic pre-solve save
  snapshots remain a later serialization/clock contract.
- Rejected and rolled-back events require an Error/Fatal diagnostic but remain
  non-authoritative; `EventLogV1` admits committed events only. Diagnostic and
  event ordering is canonical and deterministic.
- Channel event owners require a validated `CoreTopology` and a legal channel
  ID. Named refuelling, burnup, and command event bodies remain deferred to
  their bounded Phase 3 tasks.
- A later codec task must preserve the approved fixed serialized
  `VersionLifecycleV1` projection from P2-T05; the in-memory validation context
  does not authorize a schema change.
