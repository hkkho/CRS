# P5-T03 - Named refuelling events and basic discharge audit records

## Outcome

Status: COMPLETE

P5-T03 adds the approved immutable `RefuelMappingBodyV1` and
`RefuelAtomicityBodyV1` payloads, explicit applicability wrappers, and
`PositionBindingV1` validation. Public mapping bodies now reject duplicate,
gapped, reordered, or cross-channel old/new position domains. Event creation
also binds mapping effective time and atomicity commit status to the outer
event envelope.

`RefuelAuditTransitionV1` derives the canonical moved/inserted/discharged
mapping from a P5-T02 result, creates the paired committed refuelling events,
and appends them to an immutable `EventLogV1` only after both records validate.
It returns deterministic `RefuelDischargeRecordV1` evidence over the fields
currently represented by `BundleState`.

Effectiveness: SUCCESS

This task does not claim the complete P2-T03 I/Xe-bearing `DischargeRecordV1`
or `RefuelTransactionV1` projection. The current `BundleState` does not yet
own power history, coefficient binding, nuclide envelopes, history digests, or
canonical state bytes; this report preserves that boundary rather than
inventing defaults or digests.

## Assumptions and design choices

- `RefuelMappingBodyV1` follows the approved P2-T05 field order in memory:
  scheme ID, effective time, shift count, moved IDs, inserted IDs, discharged
  IDs, and canonical `PositionBindingV1` entries. The body has no command ID;
  the outer mapping event identity is the command identity, as specified.
- Old and new position domains are explicitly applicable, single-channel,
  contiguous, gap-free, strictly ascending within each mapping category, and
  complete for the inferred channel position count. Inserted and discharged
  positions are validated as endpoint trains through the generated P5-T02
  mapping; the public body cannot accept a partial or cross-channel mapping.
- `RefuelAtomicityBodyV1` requires supplied pre-state and proposed-state
  `Digest32` identities. This task does not calculate a location-only digest
  and does not present one as the complete P2-T03 transaction digest.
- `RefuelAuditTransitionV1` uses the P5-T02 immutable source/result pair,
  supplied state binding, command identity, event identity, sequence, and
  complete-state digest inputs. It appends mapping then atomicity through
  immutable `EventLogV1` values; failure of either append leaves the caller's
  original log unchanged.
- `RefuelDischargeRecordV1` is deliberately named as a bounded basic audit
  record and contains only the current `BundleState` fields plus discharge
  time/end, command identity, and core-state version. It is not substituted
  for the normative complete I/Xe-bearing `DischargeRecordV1`.
- P1-T08 literature applicability is `NotApplicable` for authority or numeric
  selection: this task selects no equation, constant, unit, normalization,
  coefficient, tolerance, reference case, golden value, or physics rule.
  Refuelling-related candidate rows `S1-R07`, `S4-R03`, `S4-R04`, `S5-R05`,
  and `S6-R05` were inspected as background/candidate-design evidence only.
- `G2` remains exactly `FORCED CLOSED / WAIVED`. P5-T03 is eligible under the
  gate-overlap rule because it consumes frozen P2-T05/P5-T02 contracts and
  does not depend on the blocked P4-T06 DONJON5 admission.
