## Assumptions and design choices

- The case is `Synthetic` coverage only. It is a mathematical manufactured
  solution for the frozen P2-T02 operator and normalization contract, not a
  physics-data baseline.
- The Core operator's approved leakage rule is preserved exactly: explicit
  edge/boundary leakage is divided by the node volume before it is added to the
  removal operator. The standalone implementation independently reproduces
  that rule; it does not call `ReactorSim.Core`.
- The exact positive flux shapes and eigenvalue are authored first. Downscatter
  and fission coefficients are derived so both group equations hold at the
  declared eigenvalue. The generator fails closed if a derived coefficient is
  nonfinite, nonpositive where required, or violates absorption/fission
  invariants.
- No nuclear-data library or external solver input is used. The artifact says
  `NotApplicable` with a concrete synthetic-coefficient reason; it does not
  imply missing external data is acceptable for a production reference.
- The source program field records the exact generator identity, version, build
  target, coupling identity, and content hashes. The repository has no
  committed HEAD in this workspace, so the source commit field is explicitly
  `UNAVAILABLE`; this is a limitation for the fresh gate to review, not a
  silently invented commit.
- P1-T08 applicability: `S1-R02`, `S1-R03`, `S1-R05`, `S1-R11`, `S5-R03`,
  `S5-R04`, and `S5-R09` are context/methodology and authority-gap rows only;
  they provide no numeric authority for this case. `S6-R03` is methodology
  context for lower-dimensional two-group workflows. `S1-R04`, `S1-R06`,
  `S1-R07`, `S5-R05`, and `S5-R06` are `NotApplicable` because this case uses
  no CANDU geometry, WIMS/JEFF data, burnup history, or SERPENT comparison.
  RRS, poison, refuelling, and kinetics rows are `NotApplicable` because this
  static case contains none of those behaviors; `S6-R08` is explicitly
  `NotApplicable` for the same reason.
