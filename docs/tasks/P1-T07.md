# P1-T07 - Integrate the fixed reference parsers into a repeatable workflow

## Outcome

Status: COMPLETE

Implemented the repeatable offline P1-T07 workflow for the fixed P1-T02 DRAGON5
and P1-T03 DONJON5 smoke cases. The workflow consumes the existing external
run records, verifies their descriptor/tool/runner identities and raw-artifact
hashes, invokes the existing P1-T05/P1-T06 exporters twice per case, requires
byte-identical compact output, validates the P1-T04 compact and raw-run
schemas, and writes manifests/hashes only beneath a new external directory.
It never copies raw listings, stderr, Version5 source, HDF5 inputs, nuclear
data, or reference outputs into the repository.

## Files created or changed

- `tools/PhysicsData/Run-P1-T07-ReferenceWorkflow.ps1` - external-only workflow
  that produces two compact exports per case, two P1-T04 raw-run manifests,
  and a deterministic repeat-hash report.
- `tools/PhysicsData/Test-P1-T07-ReferenceWorkflow.ps1` - focused synthetic
  external-fixture, schema, byte-repeat, provenance, and path-safety harness.
- `reference/README.md` - reproducibility instructions and external output
  layout for the P1-T07 workflow.
- `docs/tasks/P1-T07.md` - this report.

Pre-existing parsers, runners, descriptors, schemas, fixtures, Core/CLI,
Unity, and reference provenance files were inspected and not changed. No
generated Python cache or workflow artifact is repository-visible.

## Assumptions and design choices

- P1-T07 is interpreted as the next eligible `P1-T07` task identified by the
  sprint handoff and the implementation-plan queue.
- The workflow accepts only the exact P1-T02/P1-T03 run-record formats and
  fixed descriptor/program/container identities. A stale runner hash, changed
  source identity, altered raw-artifact hash/size, non-offline record, or
  repository-local input/output path fails closed.
- The run record remains the source of raw listing/stderr locations. The
  workflow records their byte hashes and associates the generated compact
  export through the existing P1-T04 `compact-export` artifact role; it does
  not add fields to the closed compact schema.
- Invocation IDs are deterministic hashes of the retained listing bytes. UTC
  timestamps are normalized to the P1-T04 `Z` form, while the repeat-hash
  report contains only relative external-artifact names and stable hashes.
- Compact output remains `candidate_reference`; raw manifests and repeat
  evidence remain `retained_private`/`external-private`/`not-approved`. P1-T07
  does not approve golden data or rerun either reference program.
