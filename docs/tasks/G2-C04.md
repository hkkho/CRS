## Assumptions and design choices

- P2-T03 `BundleState` is the single owner of persistent bundle identity and
  the P2-T04 `NuclideState`; no side-table or slot-order inference is allowed.
- `NuclideTransitionRecordV1`, `NuclideStateEnvelopeV1`,
  `DischargeRecordV1`, `RefuelBatchV1`, `RefuelShiftCommandV1`,
  `RefuelTransactionV1`, and `RejectedProposedStateV1` are logical payloads
  defined in the two approved specifications. They bind the existing P2-T05
  observable bodies and do not add a new public observable kind.
- All canonical bytes use the existing P2-T05 fixed-width encodings, explicit
  applicability tags, UUIDv8 rules, length/count prefixes, and deterministic
  ordering. Digest fields exclude themselves. Refuelling uses the fixed P2-T05
  status ordinals: `Committed=0`, `RolledBack=1`, `Rejected=2`, and
  `NotApplicable=255`.
- A fresh v1 template has current I/Xe inventories exactly equal to explicit
  initial inventories and an empty history with a real empty-history digest.
  Moved bundles retain atom inventories, initial values, versions, data
  identity, and history; only destination volume changes and densities are
  recomputed.
- A mapping/atomicity pair is linked by the outer P2-T05 `EventV1.EventId` and
  `RefuelAtomicityBodyV1.CommandId`. Equal-time batches carry the complete
  sorted command set and share full-batch before/proposed digests. Rejected
  batches return diagnostics without appending committed event-log state.
- The literature digest was used only for provenance applicability: S1-R07,
  S1-R09, S5-R05/S5-R08, and S6-R05. No literature numeric value was admitted.
