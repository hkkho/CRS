# P1-T04 - Raw-run and compact reference-output schemas

## Outcome

Status: COMPLETE

Defined two strict JSON Schema Draft 2020-12 contracts for the two Phase 1 Version5 smoke cases:

- an external/private raw-run retention manifest that records the exact case, tool, runner, listing, separately captured stderr, hashes, timestamps, structured warning/error evidence, assertions, convergence, and truthful success/failure state without embedding an upstream payload; and
- a deterministic compact export that retains only stable semantic observations and source diagnostics, with no run UUID, timestamp, host fact, local path, raw-listing hash, timing/memory text, invented geometry, or acceptance tolerance.

The compact DRAGON branch contains exactly the three ordered source `FINAL KINF` observations plus the known assertion and final-external-convergence occurrence counts. The compact DONJON branch contains exactly one FLDDIR K-EFFECTIVE physics observation; the assertion occurrence, warning count, outer iteration, DELS, DELT, and EPSOUT remain diagnostics. Both schemas are closed, versioned, fail-closed, and limited to the exact P1-T02/P1-T03 case/program pairs.

Four valid schema-only examples, eleven schema-invalid examples, two strict-JSON lexical negatives, and one semantic value/lexeme mismatch fixture were added. The validator independently checks schema validity, expected error paths, finite numbers, duplicate names, scalar lexeme agreement, UTC/time ordering, outcome consistency, case/program and descriptor/tool identity, listing/stderr retention, DONJON `DELT <= EPSOUT` evidence, and exact repeatable compact rendering.

Independent Sol review returned PASS with no remaining finding. This task does not approve golden/reference data, redistribute upstream artifacts, define a runtime data-pack schema, or implement either parser.

## Assumptions and design choices

- v1 is intentionally closed to `dragon5-lumpss-v5.1.0-source-era`/DRAGON5 and `donjon5-afa-180-310-type1-dual-v5.1.0`/DONJON5. A new case family or changed meaning requires a new schema version.
- Raw artifact SHA-256 values identify retained bytes only; variable listing bytes are not semantic-equality criteria.
- Raw manifests require an external listing and the separately captured program stderr, including a zero-byte stream. Artifact content is never embedded and every artifact remains `external-private`/`not-approved`.
- A failed manifest validation can truthfully record `normal_end: true` when post-run validation rejects an otherwise normally terminated program. A successful manifest requires normal end, no error codes, passed assertions, and converged source evidence.
- Compact outputs contain stable case/tool provenance but no link to one run-specific raw hash. P1-T07 may associate the formats without making compact bytes run-specific.
- Compact examples are `unapproved_schema_example`; future parser output may be `candidate_reference`. Both remain external/private and publication-not-approved. Approval is a gate decision outside the byte format.
- Numeric JSON values are finite and authoritative. `source_lexeme` is mandatory audit evidence and must have the same exact decimal value. `unit_id: "1"` is used only for dimensionless physics observations; source convergence diagnostics receive no invented unit.
- Deterministic compact bytes use strict UTF-8 without BOM, LF, fixed insertion/key/array order, two-space indentation, the documented separators, and one terminal LF. This project contract does not claim RFC 8785 canonicalization.
- The committed examples repeat only minimal scalar evidence already documented by P1-T02/P1-T03. They are schema fixtures, not reference-baseline approval or redistribution permission.
