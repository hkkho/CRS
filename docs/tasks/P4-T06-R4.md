## Assumptions and design choices

- The offline candidate format is a versioned JSON artifact and manifest; it is
  not a new public runtime schema. The runtime-facing projection remains the
  existing `BurnupCoefficientTableV1` contract.
- R4 is intentionally synthetic-only. The source and output require
  `evidence_class: synthetic`; external/reference evidence classes are rejected
  instead of being silently admitted by a validator intended for this bounded
  candidate.
- The candidate pack carries the fixed path-free artifact ID
  `p4-t06-r4-reduced-candidate-v1`, and the manifest must bind to the same ID.
  Table ordering is explicit by material variant ID and table ID.
- Each table checksum is SHA-256 over deterministic LF-terminated JSON for the
  table identity and ordered rows, excluding the checksum itself. Pack and
  source byte digests are recorded in the manifest; regeneration requires byte
  equality.
- Existing Core validation supplies the approved SI meanings and row/table
  invariants: burnup `J/kg_HM`, coefficient and downscatter values `m^-1`,
  `ChiGroup1` dimensionless, and energy per fission `J`. No topology, volume,
  conductance, direction, or normalization is inferred.
- No extrapolation, clamping, smoothing, repair, hidden defaults, or DONJON5
  runtime dependency is introduced. Unknown and duplicate JSON fields are
  rejected.
