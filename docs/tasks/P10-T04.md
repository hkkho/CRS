## Assumptions and design choices

- The approved Phase 8 `100 ms` control tick, default `10x` acceleration, and
  explicit wall-time ownership remain unchanged; Controls only submits wall
  durations.
- Target fields use invariant presentation parsing and leave domain bounds to
  the existing runtime port. Invalid or non-finite text is rejected locally
  without a runtime call.
- No irreversible command exists in the current adapter vocabulary, so no
  confirmation/cancel control is introduced here. A later refuelling task must
  add its own authority before exposing such a command.
- The graphical surface is built during `Awake` when attached to the shell.
  `Bind` enables the surface; `Unbind` returns it to the disabled waiting state.
  This makes the visual acceptance independently observable without inventing
  a fake runtime port or simulation state.
- The visible demo uses a normal `StandaloneWindows64` BuildPipeline player.
  Unity Test Runner players are retained only for headless test evidence and
  are not used as the graphical demo. The project launcher removes stale
  project-owned Test Runner players before a visual launch so they cannot
  interfere with the demo's Windows permission surface.
- The repository-local `.codex/config.toml` already marks the project trusted
  for autonomous repository work. Host-level Computer Use access remains a
  Codex/Windows permission and is not changed by Unity or repository code.
- Literature applicability: `NotApplicable`; this task changes presentation
  only and selects no physics or reference/golden authority.
