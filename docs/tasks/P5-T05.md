# P5-T05 - Burnup-indexed coefficient-table validation and lookup

## Outcome

Status: COMPLETE

P5-T05 implements the approved bounded coefficient-table contract. Immutable
Core values validate finite two-group material coefficients, positive energy
per fission, nonnegative forbidden terms, absorption/fission relationships,
fission-support consistency, and the approved `chi` constraints. Immutable
rows and tables retain stable identity, schema/data/material/unit/provenance
metadata, and an opaque loader-supplied checksum. Tables reject missing or
invalid metadata, private file-path provenance, invalid rows, and duplicate or
reordered burnup knots without sorting caller input.

Lookup accepts only finite, nonnegative burnup inside the strict table domain.
Exact knots return source rows with the specified endpoint fraction; interior
values use the adjacent bracket and the approved scalar linear interpolation
rule. `chi_1` is interpolated and `chi_2` is derived as `1 - chi_1`, followed by
full invariant revalidation. Out-of-range burnup and invalid interpolation
states fail closed. Lookup results retain table/material/unit/checksum identity,
bracket indices, input burnup, fraction, and resolved values.

Effectiveness: SUCCESS

## Assumptions and design choices

- The approved P2-T02 coefficient invariants and P2-T03 burnup-indexing rules
  are the authorities. The digest rows `S1-R04`, `S1-R05`, `S5-R03`, `S5-R04`,
  and `S5-R05` are background/candidate evidence only; no reported literature
  number or coefficient was copied into runtime code.
- The table stores material coefficients only. Geometry-dependent volume and
  conductance data remain outside this bounded table contract, consistent with
  the existing spatial-node/operator boundaries.
- The checksum is an opaque `Digest32` supplied by the data-pack/loader
  boundary. No canonical byte serializer or checksum algorithm was invented;
  verification and compatibility admission remain the owning data-pack task.
- Table rows are accepted only in caller-supplied canonical increasing burnup
  order. The table never sorts, repairs, clamps, extrapolates, or substitutes
  a nearest knot.
- Exact lower/interior knots report fraction `0`; an exact upper endpoint of a
  multi-row table reports fraction `1`, while all scalar values remain the
  source row. `chi_2` is always derived after `chi_1` handling.
- Non-URI path-like provenance is rejected, including rooted POSIX, UNC,
  Windows-drive, and separator-containing private paths. URI provenance may be
  retained as descriptive source metadata; it is not a runtime file loader.
- `G2` remains exactly `FORCED CLOSED / WAIVED`. P5-T05 is eligible under the
  non-critical gate-overlap policy because it consumes frozen contracts and
  does not depend on the blocked P4-T06 reference admission.
