# G0 - Phase 0 architecture and toolchain review

## Result

FAIL

The Phase 0 architecture and current Windows toolchain are operational: the
headless T3 baseline, clean-source build, Unity import/compile/scene smoke, and
desktop-player T4 build all pass. The gate nevertheless fails because two
explicit infrastructure requirements remain unsafe or absent. The focused-test
wrapper returns success when an exact test name matches no test, and Phase 0
never selected or pinned the serialization strategy required by the execution
baseline. These defects must be corrected independently and G0 rerun before any
Phase 1 task is eligible.

## Findings

### High: Phase 0 has no selected or pinned serialization strategy

- Location: `docs/Implementation_plan.md:288` and
  `src/ReactorSim.Core/ReactorSim.Core.csproj:1`.
- Evidence: the plan explicitly requires the serialization library to be pinned
  in Phase 0. Core has no package reference, central version pin, ADR, or
  documented framework-library choice.
- Impact: silently deferring this would push a cross-project, save/replay,
  Unity-dependency, and mobile AOT decision into later implementation.
- Required action: `P0-T08` (Sol max) must choose and document the
  engine-neutral serialization strategy, pin applicable versions
  machine-readably, account for Unity dependency copying and IL2CPP/AOT
  feasibility, and run T3 plus clean-source T4 import/player smoke.

### High: Focused-test wrapper succeeds when zero tests match

- Location: `tools/Test-Focused.ps1:45`.
- Evidence: VSTest returned 0 for the syntactically valid nonexistent exact FQN;
  the wrapper therefore returned success after printing the no-match message.
- Impact: a renamed, mistyped, or undiscovered test can produce false T1
  evidence, defeating the repository's mandatory per-task validation policy.
- Required action: `P0-T07` (Luna max) must consume machine-readable test
  results and prove that the requested exact FQN executed and passed. It must
  include positive and valid-but-absent negative checks. The T3 wrapper must
  also reject a solution in which no test executes.

### Medium: Automation is not yet a complete cross-platform surface

- Location: `tools/Test-UnityImport.ps1:24`,
  `tools/Test-UnityImport.ps1:41`, `unity/README.md:34`, and
  `docs/tasks/P0-T04.md:197`.
- Evidence: PowerShell 7 is not documented or validated on macOS/Linux; default
  editor discovery and executable product-version inspection are Windows
  specific. An explicit editor path mitigates discovery but not PE metadata
  assumptions.
- Impact: the Windows G0 baseline is reproducible, but this wrapper cannot yet
  serve as the proven macOS fallback needed for later iOS work.
- Required action: deferred `P0-T09` before the first non-Windows Unity or iOS
  automation task. Document the cross-platform PowerShell prerequisite, make
  editor discovery/version validation host-aware, and add a bounded editor
  timeout. This does not need to precede `G0-R1`, which remains scoped to the
  proven Windows baseline.

## Requirements and boundary review

- Dependency direction: PASS. Core is engine-neutral and reference-free;
  CLI/tests reference Core; Unity consumes only the generated Core DLL through
  the thin adapter assembly.
- Determinism: not applicable to simulation behavior. No simulation clock, RNG,
  save/replay, or numerical transition exists. Cross-root build metadata
  differences are documented and do not change this gate's result.
- Failure handling and diagnostics: FAIL. The Unity T4 marker and process-exit
  safeguards fail closed, but the focused T1 wrapper accepts an empty exact-test
  selection and the T3 wrapper does not assert a nonzero executed-test total.
- Scope exclusions preserved: PASS. No simulation/gameplay behavior, reactor
  equations, OpenMC, DRAGON5/DONJON5 runtime dependency, shutdown/scram, full
  thermal hydraulics, native mobile dependency, or signing material was added.
- Licensing/provenance: PASS for Phase 0. Unity activation remains external;
  no credential or license artifact is tracked. Reference-tool licensing is a
  Phase 1 activity and was not pre-empted.
- Version pins: FAIL. .NET, test, Unity, CLI, and formatting pins are explicit;
  the required serialization pin/strategy is absent.
- Mobile feasibility: PASS with a deferred automation risk. The architecture
  has no native dependency and the prerequisites accurately bound Android and
  iOS requirements; T5 remains appropriately deferred.
