## Findings

### High: Complete T4 evidence is missing

- Location: `docs/spec/observables-validation-methodology-v1.md` validation
  tier requirement; `tools/Test-UnityImport.ps1` import-smoke path.
- Evidence: P2-T05 records import/compile smoke only, while the methodology
  requires actual Unity EditMode, PlayMode, and desktop-player smoke suites.
- Impact: G2 cannot claim complete serialization/core-adapter evidence.
- Required action: obtain an authorized bounded task and available Unity/editor
  environment to run and record all three T4 portions outside the repository.

### High: Snapshot/version serialization lifecycle is underdefined

- Location: `docs/spec/observables-validation-methodology-v1.md` StateBinding
  and serialization fields; `docs/spec/refuelling-burnup-transitions-v1.md`
  snapshot/state-version contract; corresponding P2-T04 nuclide state fields.
- Evidence: `PowerSnapshotVersion` is serialized by P2-T05, but P2-T03 does
  not define its lifecycle; `SpatialStateVersion` and `NuclideStateVersion`
  lack complete initialization, increment, invalidation, and rollback rules.
- Impact: snapshots, replay, rollback, and deterministic cross-subsystem
  bindings are not implementable without inventing state transitions.
- Required action: define one cross-spec version model, including initial
  values, commit increments, invalidation, rollback, and serialization
  relationships.

### High: RRS queue transitions and equal-time ordering are incomplete

- Location: `docs/spec/kinetics-xenon-rrs-feedback-v1.md` controller update and
  due-command sections and event-rank table.
- Evidence: command generation and due-command consumption are described
  separately, but due-time construction, zero-delay enqueue/consume behavior,
  and a controller-command-generation rank are not fixed.
- Impact: equal-time command ordering and controller state transitions can be
  nondeterministic or require unapproved interpretation.
- Required action: define command records, `DueTime` construction, enqueue and
  consume ordering, zero-delay behavior, and atomic pre/postconditions.

### High: Refuelling atomicity omits later-added nuclide state

- Location: `docs/spec/refuelling-burnup-transitions-v1.md` rollback set and
  `docs/spec/kinetics-xenon-rrs-feedback-v1.md` I/Xe bundle-state contract.
- Evidence: P2-T03 rollback omits nuclide inventory/version/digests, while
  P2-T04 requires I/Xe state to move and discharge with bundle identity.
- Impact: a failed refuelling command cannot be proven byte-for-byte atomic
  across all authoritative state.
- Required action: extend refuelling preconditions, postconditions, discharge
  records, and rollback to all nuclide state.

### Medium: Plan requirement 13 conflicts with deferred numeric thresholds

- Location: `docs/Implementation_plan.md` requirement 13 and
  `docs/spec/observables-validation-methodology-v1.md` provisional-profile
  status rules.
- Evidence: the plan calls for quantity-specific provisional tolerances, while
  P2-T05 intentionally defers every numerical threshold and forbids inventing
  one.
- Impact: approving G2 would either violate the plan or require unauthorized
  numeric values.
- Required action: supply evidence-backed provisional thresholds through an
  authorized specification change, or obtain an approved plan amendment. Do
  not invent thresholds or loosen tolerances.

### Medium: P2-T05 focused evidence is not reproducible as reported

- Location: `docs/tasks/P2-T05.md` focused-check entry.
- Evidence: the report describes the inline assertion command in prose rather
  than recording the complete runnable command or a committed harness.
- Impact: the required exact-command audit trail is incomplete even though the
  root run passed.
- Required action: amend the task report or provide an approved external
  harness with the complete command and exact output, then rerun the affected
